# 05. AI

Everything that talks to a model lives in `packages/ai`. The app calls functions such as `generatePortfolio(profile, options)`; it never builds a prompt or calls a model SDK itself.

## 1. The two rules, as engineering constraints

**The AI never invents facts.**

- The model's input is the user's master profile and nothing else about them. Prompts tell it to rewrite, structure and sharpen, and to leave out what is not in the profile.
- Every prompt that writes copy states this rule explicitly and tells the model what to do when detail is missing: return a gap, not a guess.
- **Gaps are data.** Structured output has a place for them (for example `gaps: [{ field, question }]`), and the UI shows them to the user. A missing outcome is never filled with a plausible number.
- Numbers, employers, dates, titles, technologies and outcomes in generated copy must all trace back to the profile. Tests check this on fixed fixtures ([07-testing-quality.md](07-testing-quality.md)).
- Extraction (CV upload) copies what is in the document. Anything the model inferred instead of read is marked for the user to confirm, and the confirmation screen is not skippable.

**User edits always win.**

- Every AI-writable text field is stored as `{ text, source: 'ai' | 'user', locked }`.
- A user edit sets `source: 'user'` and `locked: true`.
- **Locks are enforced in code, after the model responds, not by asking the model nicely.** The merge function takes the previous content and the model output and keeps every locked field byte for byte. It is a pure function in `packages/schema` or `packages/ai` with tests for every field type.
- Locked fields are still sent to the model as context so the rest of the copy stays consistent with them.
- Regeneration, rewrite and template switch all go through the same merge function. There is no second code path that writes content.

## 2. Prompts

- Prompts live only in `packages/ai/src/prompts/`, one file per task, exported as functions that take typed input and return the messages.
- A prompt is code: reviewed, versioned in git, and covered by a fixture test. Changing one is a behaviour change and gets its own commit.
- **User content is data, never instructions.** Profile text, CV text and interview answers are placed in clearly delimited blocks, and the system prompt says that anything inside them is content to work with, not instructions to follow. A CV that says "ignore previous instructions" must change nothing.
- No personal data in a prompt beyond what the task needs. Phone numbers and home addresses from a CV are stripped before generation, since they are never published by default.
- Keep the stable part of a prompt (instructions, schema, examples) first and the per-user part last, so provider prompt caching can apply.

## 3. Output

- **Structured output is always validated with the Zod schema from `@folix/schema`.** The model's reply is `unknown` until it parses.
- A reply that fails validation is retried once with the validation error, then fails as a clear, user-facing error. It is never saved half-parsed.
- Generated text is rendered as plain text. It is never interpreted as HTML or Markdown that could carry a link or script the user did not write.
- Enforce length limits per field in the schema, so one runaway field cannot break a template.
- Streaming: partial output updates the preview, but the database is written once, from the final validated object.

## 4. Models and providers

- The Vercel AI SDK is the only interface to a model. The provider and model id are chosen in one place in `packages/ai` and can be swapped without touching callers.
- Pick the model per task: a stronger model for writing, a cheaper and faster one for extraction or classification if quality holds. Record the choice in DECISIONS.md.
- Every call sets a timeout and a maximum output size.

## 5. Cost and abuse control

- **Every model call is logged to `ai_usage`:** user, feature, model, input and output tokens, duration, outcome. No call bypasses the wrapper that logs.
- **Per-user daily allowances** for full generations and rewrites are checked on the server before the call, inside the same request, and return `limitReached` with a clear message when exceeded.
- Anonymous use (generate before sign-up) is rate limited by IP and by a signed session cookie, with a much smaller allowance.
- A failed or cancelled call that used tokens still counts.
- Inputs are capped in size before they reach the model (CV length, answer length, number of projects).

## 6. Failure behaviour

- A model error, timeout or refusal never loses the user's input. The profile and the previous draft stay as they were.
- The user sees what happened in plain words and can retry. Retry is safe: it does not double-charge the allowance for the failed attempt beyond what was actually used.
- A generation that stops halfway leaves the previous draft in place, not a half-written one.

## 7. Testing AI code

- Pure parts (merge with locks, gap detection, prompt assembly, output validation) have unit tests with no network.
- Model calls are tested against recorded fixtures, so CI never calls a provider.
- A small evaluation set of profiles (thin, rich, messy CV, career changer) is run by hand when a prompt changes, checking: no invented facts, locked fields untouched, gaps reported, lengths within limits.
